# PRD: 알람 뉴스 브리핑 기능 (사용자 지정 키워드 뉴스 읽어주기)

## 1. 배경 및 목표

### 배경
현재 알람 앱은 설정한 시각에 알람음만 울리는 단순한 기능을 제공한다. 사용자는 아침에 알람을 끄기 전후로 스마트폰이나 PC를 통해 관심 분야(창업, 웹툰) 뉴스를 별도로 찾아보는 행동 패턴을 가지고 있다. 알람이 울리는 시점에 관심 뉴스를 자동으로 음성으로 요약해준다면, 사용자는 기상과 동시에 정보 습득을 시작할 수 있어 별도의 뉴스 검색 행위 없이 하루를 시작할 수 있다.

### 목표
- 알람이 울릴 때 사용자가 지정한 키워드(최대 2개, 미지정 시 "스타트업"/"웹툰" 기본값)의 최신 뉴스를 각 5건씩 자동으로 가져와, 알람을 끄기 전까지 순차적으로 음성(TTS)으로 읽어준다.
- 네이버 뉴스 검색 API를 활용하되, API 키는 서버(Supabase Edge Function)에서만 다루어 보안을 확보한다.
- 뉴스 브리핑은 알람의 핵심 기능(소리 울림)을 절대 방해하거나 지연시키지 않는 부가 기능으로 동작한다.
- "최근뉴스" 화면에서 사용자가 뉴스를 직접 조회·새로고침하고, 원하는 기사를 체크해 Google Sheets에 기록할 수 있다.

## 2. 사용자 스토리

- 사용자로서, 아침 알람이 울릴 때 스타트업 관련 최신 뉴스를 음성으로 들려주었으면 한다. 그래야 알람을 끄면서 바로 오늘의 스타트업 소식을 파악할 수 있다.
- 사용자로서, 웹툰 관련 최신 뉴스도 함께 들었으면 한다. 그래야 좋아하는 웹툰의 신작/업데이트 소식을 놓치지 않을 수 있다.
- 사용자로서, 알람을 끄지 않는 한 다음 뉴스가 계속 이어서 읽히길 원한다. 그래야 완전히 깨어날 때까지 정보를 계속 들을 수 있다.
- 사용자로서, 뉴스 브리핑을 듣는 도중에도 알람을 정상적으로 끌 수 있어야 한다. 그래야 브리핑이 길어져도 아침 일정에 지장이 없다.
- 사용자로서, 네트워크 문제나 뉴스 API 장애가 발생해도 알람 소리는 반드시 울려야 한다. 그래야 뉴스 기능 오류 때문에 늦잠을 자는 일이 없다.
- 사용자로서, 최근뉴스 목록에서 "새로고침"을 누르면 항상 최신 상태로 다시 조회되고, 새로 추가된 기사에는 "NEW" 표시가 붙었으면 한다.
- 사용자로서, 최근뉴스 목록에서 마음에 드는 기사를 체크해서 골라두었다가, "지금 저장"을 누르면 그 기사만 Google Sheets에 기록되었으면 한다.
- 사용자로서, 뉴스 카드를 클릭하면 바로 원문 기사로 이동했으면 한다. "원문보기" 링크를 정확히 클릭하지 않아도 되도록.
- 사용자로서, 그날그날 관심사가 다를 수 있으니 "스타트업"/"웹툰"에 고정되지 않고, 직접 키워드를 검색해서 원하는 것으로 지정해두고 싶다. 그래야 관심사가 바뀌어도 계속 유용하게 쓸 수 있다.

## 3. 기능 요구사항

1. **알람 트리거 연동**
   - 알람이 울리는 시점에 뉴스 브리핑 로직이 트리거된다.
   - 뉴스 브리핑은 알람음 재생과 병렬적으로(또는 알람음 재생을 막지 않는 방식으로) 동작한다.

2. **뉴스 조회**
   - 사용자가 직접 지정한 키워드(최대 2개, 미지정 시 "스타트업"/"웹툰" 기본값) 기준으로 각 최신 뉴스 5건씩을 네이버 뉴스 검색 API로부터 조회한다.
   - 조회는 클라이언트가 아닌 서버(Supabase Edge Function)를 경유하여 수행한다.
   - 응답 데이터는 title, description, link, pubDate를 포함하며, 화면 표시/TTS 전 HTML 태그는 제거하여 정제한다.
   - 제목과 설명은 잘라내지 않고 전체를 표시/재생한다.

3. **키워드 검색 및 지정 (사용자 지정 키워드)**
   - "최근뉴스" 화면에 검색창이 있어, 사용자가 임의의 키워드를 검색해 결과를 미리 볼 수 있다.
   - 검색 결과에서 "이 키워드 지정하기"를 누르면, 해당 키워드가 지정 키워드 목록(최대 2개)에 추가되어 이후 "최근뉴스" 목록과 알람 TTS 브리핑 모두 이 키워드 기준으로 조회된다.
   - 이미 2개가 지정된 상태에서 새 키워드를 지정하려 하면, 기존 2개 중 하나를 선택해 교체한다.
   - 지정된 키워드는 각 섹션 제목 옆 "✕"로 지정 해제할 수 있다(0개까지 가능하며, 0개인 경우 뉴스 조회를 생략하고 안내 문구만 표시한다).
   - 지정 키워드는 브라우저 localStorage에만 저장하며(기기별 개별 설정), 서버/DB에는 저장하지 않는다.

4. **새로고침 및 캐싱**
   - "최근뉴스" 화면을 열면 직전 조회 결과(localStorage 캐시)를 먼저 보여주고, "새로고침"을 누르면 매번 강제로 다시 조회한다(당일 캐시라도 스킵하지 않음).
   - 재조회에 실패하면 기존 캐시를 그대로 유지해서 보여주고, "갱신 실패 · 이전 목록 표시 중" 문구로 안내한다.
   - 재조회에 성공하면 직전 목록과 비교(diff)하여 새로 추가된 기사에 "NEW" 배지를 표시한다.
   - 마지막 갱신 시각을 화면에 작게 표시한다.

5. **음성 브리핑(TTS)**
   - 조회된 뉴스(지정 키워드 개수 × 5건)의 제목과 설명 전체를 순서대로 음성 합성하여 재생한다.
   - 키워드가 2개 이상이면 한 키워드의 뉴스만 몰아 읽지 않고, 키워드별로 번갈아(라운드로빈) 섞어서 읽는다.
   - 읽어주는 문장에 어느 키워드의 뉴스인지("○○ 키워드, ...")를 함께 언급하여 음성만으로도 구분할 수 있게 한다.
   - 화면에도 브리핑 목록 각 카드에 출처 키워드 배지를 표시하고, 현재 읽고 있는 카드를 하이라이트하여 시각적으로도 구분되게 한다.
   - 사용자가 알람을 끄지 않는 한, 전체를 다 읽은 뒤에도 계속 순환하며 다음 뉴스를 이어서 읽는다.
   - 사용자가 알람을 끄거나 브리핑 중지를 요청하면 즉시 음성 재생을 중단할 수 있다.
   - 지정된 키워드가 0개인 경우 브리핑을 생략한다(알람 소리에는 영향 없음).
   - 알람 울림 화면에서 스누즈/알람 끄기 버튼은 브리핑 목록 길이와 무관하게 항상 시간 표시 바로 아래(상단)에 고정 배치한다.

6. **오류 처리**
   - 뉴스 조회 또는 TTS 재생이 실패하더라도 알람 소리 자체의 재생/중지 기능에는 영향을 주지 않는다.
   - 실패 시 사용자에게 알람은 정상 작동하되 뉴스 브리핑만 실패했음을 알 수 있는 최소한의 피드백을 제공한다(구체적 UX는 Open Questions 참조).

7. **Google Sheets 기록 (예외적 영구 저장)**
   - 알람이 울려 실제로 음성 브리핑이 재생될 때마다, 읽어준 뉴스가 자동으로 BriefingLog 시트에 기록된다(링크 기준 중복 제외).
   - "지금 저장"을 누르면 각 알람이 마지막으로 울렸을 때 읽어준 브리핑 내용이 Alarms 시트의 해당 알람 행 "내용" 컬럼에 함께 저장된다.
   - 최근뉴스 목록에서 사용자가 체크박스로 직접 선택한 기사만 "지금 저장" 시점에 SavedNews 시트에 기록된다(체크하지 않은 기사·목록 조회 자체는 저장하지 않음). 개별 체크, 섹션별 "전체", 전체 "뉴스 전체 선택"을 지원한다.
   - 그 외 조회되는 뉴스 데이터 자체는 서버/DB에 영구 저장하지 않는다(루트 [CLAUDE.md](../CLAUDE.md) 데이터 저장 원칙 참조).
   - 지정 키워드 자체는 서버/DB나 Google Sheets에 기록하지 않고 브라우저 localStorage에만 둔다.

8. **뉴스 카드 상호작용**
   - 뉴스 카드를 클릭하면 해당 기사의 원문 링크가 새 탭으로 열린다.
   - 체크박스 클릭, "원문보기" 링크 클릭은 카드 전체 클릭과 별개로 동작하며 중복으로 새 탭이 열리지 않는다.

## 4. 비기능 요구사항 (보안 최우선)

- **[보안] 네이버 API 키(Client ID/Secret)는 프론트엔드(React 클라이언트, 브라우저 번들, 소스코드)에 절대 노출하지 않는다.** 반드시 Supabase Edge Function 등 서버 환경변수/시크릿으로만 관리하고, 네이버 API 호출은 서버 사이드에서만 수행한다.
- **[데이터 보관] 뉴스 데이터는 DB(Supabase DB 등 영구 저장소)에 저장하지 않고, 매 요청마다 네이버 API를 실시간 조회하여 응답한다.** (클라이언트 측 당일 캐시는 기능 요구사항 4항에 따라 허용되나, 이는 서버/DB 저장과는 별개다.)
- **[가용성] 뉴스 브리핑 기능(조회 실패, TTS 실패, 네트워크 지연 등 어떤 이유로든)이 실패해도 알람 소리 자체는 반드시 정상적으로 울려야 한다.** 알람음 재생 로직은 뉴스 브리핑 로직과 독립적으로 동작해야 하며, 뉴스 관련 예외가 알람 재생 흐름을 막거나 지연시켜서는 안 된다.
- **[통신 보안] 클라이언트-Edge Function 간, Edge Function-네이버 API 간 통신은 HTTPS를 사용한다.**
- **[비밀정보 관리] API 키 등 민감 정보는 Supabase 프로젝트 Secrets로만 관리하며, 코드 저장소(git)에 커밋되지 않아야 한다.**
- **[CORS/접근 제어] Edge Function은 알람 앱 클라이언트에서만 호출 가능하도록 최소한의 접근 제어를 고려한다.** (구체적 정책은 Open Questions 참조)
- **[성능] 뉴스 조회 지연이 알람 인지(소리/화면 표시) 자체를 블로킹하지 않아야 한다.**

## 5. 범위 제외 (Out of Scope)

- 3개 이상의 키워드 동시 지정 (현재는 최대 2개)
- 여러 기기 간 뉴스 캐시·지정 키워드 동기화 (DB 기반으로의 전환)
- Google Cloud TTS, 네이버 클로바 보이스 등 고급 TTS 엔진으로의 교체
- PWA / Service Worker를 통한 백그라운드(탭 종료 상태) 알람·브리핑 동작
- 앱 내부에서 뉴스 원문 전체를 보여주는 상세 화면(클릭 시 외부 원문 링크로 이동하는 것과는 별개)
- 다국어(한국어 외) 뉴스/TTS 지원

- Edge Function에 대한 인증/접근 제어 정책(예: Supabase Auth 토큰 검증 여부, 익명 호출 허용 여부) 미정.
- 네이버 뉴스 검색 API의 일일/분당 호출 한도 초과 시 대응 정책(재시도, 사용자 안내 등) 미정.
- TTS 음성 속도(rate), 목소리 종류 등을 사용자가 조절 가능하게 할 것인지 미정.

## 7. 성공 기준

- 알람이 울릴 때 지정 키워드별 뉴스 5건씩이 정상적으로 조회되어 음성으로 읽히고, 알람을 끄지 않는 한 계속 순환 재생됨을 확인한다(정상 네트워크 환경 기준).
- 최근뉴스 화면 검색창에서 키워드를 검색하고 지정하면, 이후 최근뉴스 목록과 알람 브리핑이 해당 키워드로 조회됨을 확인한다.
- 네이버 API 키가 클라이언트 번들, 네트워크 요청(브라우저 개발자 도구 Network 탭), 소스 저장소 어디에도 노출되지 않음을 확인한다.
- 뉴스 API 또는 TTS를 강제로 실패시키는 테스트(네트워크 차단, Edge Function 오류 반환 등)에서도 알람 소리가 정상적으로 울리는 것을 확인한다.
- Supabase DB 또는 서버 영구 저장소에 뉴스 데이터 자체가 저장되지 않고, 매 요청마다 실시간으로 네이버 API를 호출함을 확인한다(단, 알람 시 읽어준 브리핑 내용과 사용자가 체크한 기사만 Google Sheets에 예외적으로 기록됨은 루트 CLAUDE.md 기준대로 유지).
